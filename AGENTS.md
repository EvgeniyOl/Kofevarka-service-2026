# Правила работы с проектом

## Язык

- Отвечай и рассуждай **по-русски**: сообщения, планы, пояснения к правкам, итоги.
- Комментарии в коде, тексты интерфейса и документация — тоже на русском
  (так уже написаны все файлы проекта, держим единый язык).

## Стили

- Только CSS Modules: файл `<Компонент>.module.css` рядом с компонентом.
- Классы — `camelCase` или одно слово, без БЭМ-разделителей (`-`, `__`).
- Глобальным остаётся единственный файл `src/index.css`: сброс, дизайн-токены, общие keyframes.
- Общие примитивы (кнопки, карточки, поля, сетки) — в `src/styles/ui.module.css`.
- Динамические классы собираются через `cx(...)` из `src/utils/cx.ts`.
- Дизайн-токены берём из `:root` (`--accent`, `--cream`, `--muted`, `--radius`, `--ease`),
  а не подставляем цвета и радиусы числами.
- Картинок и шрифтов извне не тянем: весь визуал — CSS и SVG. Исключение — фотографии
  товаров и героя в `public/photos`: у каждой должна быть запись в `public/photos/CREDITS.md`
  с лицензией (берём CC0 или файлы заказчика). Новые зависимости — только после согласования.

## Контент

- Сайт информационный: заказы принимаем по телефону и заявкой, корзины и онлайн-оплаты нет.
  Кнопки покупки не добавляем — вместо них «Уточнить наличие» и переход на контакты.
- Телефон, почта и адрес живут в `src/data/contacts.ts`, а не в разметке страниц.
- Цифры со словами («4200 машин») выводятся через `StatValue`: он держит отступ
  между числом и суффиксом. Собирать такую строку вручную нельзя — получается «4200машин».

## Состояние

- Состояние раздела живёт в его сторе (`src/stores`), новый раздел — новый стор-класс,
  подключённый в `RootStore`.
- Компонент оборачивается в `observer(...)` и берёт сторы через `useStore()` из `stores/context`.
- Менять состояние можно только методами (action) стора — так MobX пересчитает
  computed-значения (суммы, скидки, прогресс).
- Локальный `useState` — только для чисто интерфейсных вещей: открытое меню, активный таб,
  состояние анимации. Данные приложения в компоненте не храним.

## Проверки после правок

Прогонять всегда, до того как отчитываться о готовности:

```bash
npm run typecheck   # tsc -b
npm run lint        # eslint .
npx prettier --check <изменённые файлы>
```

- Визуальные правки проверяем в браузере: dev-сервер `npm run dev` (http://localhost:5000),
  при необходимости — скриншот headless-Chrome и сравнение до/после.
- Карточки, логотипы и прочую графику смотрим глазами на увеличенном снимке, а не только
  по коду: дефекты вроде текста, вылезающего за круг, видно только так.
- Временные файлы проверки (скриншоты, тестовые страницы, профили браузера) удаляем за собой,
  если человек не просил их оставить.
- `npm run build` внутри песочницы DSH падает на `spawn EPERM` — это ограничение среды,
  а не ошибка проекта; для сборки нужен запуск вне песочницы.

## Git

- **Коммиты и push — только по явной просьбе человека.** Закончил правку — оставь её
  в рабочем дереве и скажи, что готово; не коммить «на всякий случай» и не пушить.
- Если человек просит коммит: делай отдельные осмысленные коммиты по смыслу правки,
  с описанием, что изменилось и почему.
- Никогда не добавляй в индекс временные файлы проверки (`.tmp-shots`, профили браузера,
  скриншоты) — они в `.gitignore`, но `git add -A` их и не должен цеплять.
- Историю не переписываем (`rebase`, `commit --amend` опубликованного, `push --force`)
  без прямой просьбы.
